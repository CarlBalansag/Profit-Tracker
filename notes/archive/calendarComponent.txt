STEP 2 — API ROUTES (selvora-api/routes/calendarEvents.js)
================================================================================

Pattern: follow goals.js exactly (isAuthenticated middleware, prisma, etc.)

Endpoints:
  GET    /api/calendar-events?month=YYYY-MM
         → fetch user's manual events for month ± 1 (week-view edge)
         → filter: date >= first day of prev month, date <= last day of next month

  POST   /api/calendar-events
         → body: { title, date, end_date?, color?, notes? }
         → validate with calendarEvent schema
         → prisma.calendarEvent.create({ data: { user_id: req.user.id, ...body } })

  PUT    /api/calendar-events/:id
         → body: partial calendarEvent fields
         → verify ownership: findUnique where id AND user_id
         → prisma.calendarEvent.update

  DELETE /api/calendar-events/:id
         → verify ownership first
         → prisma.calendarEvent.delete

  GET    /api/calendar-events/auto?month=YYYY-MM
         → IMPORTANT: define this route BEFORE /:id to avoid param conflict
         → Query Inventory: purchase_date in month range
           → returns { id: inv.id, title: inv.product_name, date: purchase_date, type: 'purchase' }
         → Query Sales: sale_date in month range (join inventory for product_name)
           → returns { id: sale.id, title: product_name, date: sale_date, type: 'sale' }
         → Query Sales: payout_date in month range (where payout_date != null)
           → returns { id: sale.id+'_pay', title: product_name, date: payout_date, type: 'payout' }
         → Merge all three arrays, return sorted by date

STEP 3 — LIVE CALENDAR FEED (auto-sync, replaces one-time .ics download)
================================================================================

HOW IT WORKS:
  - Instead of a one-time file download, the API exposes a LIVE feed URL
  - User adds it to Google/Apple Calendar ONCE via "Add calendar from URL"
  - Google/Apple polls the URL every few hours and pulls the latest events
  - When user adds a sale, purchase, or manual event in Selvora, it appears
    automatically in their personal calendar on next poll — no re-export needed

AUTHENTICATION (no login cookies on this endpoint):
  - Add calendar_token field to User model (random UUID, generated on first use)
  - Feed URL uses token as query param: /api/calendar/feed.ics?token=USER_TOKEN
  - If token is missing or wrong → 401. No session needed.

NEW ENDPOINT: GET /api/calendar/feed.ics?token=XXX
  → IMPORTANT: define BEFORE /:id route, in a separate router or same file
  → Look up user by calendar_token
  → Fetch: all user manual events (no date filter — full history)
  → Fetch: inventory purchase_date (all time, or past 1 year + future)
  → Fetch: sales sale_date + payout_date (all time)
  → Build .ics string with template literals (no npm library needed)
  → Return: Content-Type: text/calendar; charset=utf-8
            (NO Content-Disposition — subscribe feeds must not force download)

NEW ENDPOINT: POST /api/calendar/token (authenticated, session-based)
  → Generate or return existing calendar_token for req.user
  → Returns { token, feedUrl }
  → Called once when user visits the Calendar page to get their subscribe URL

ICS format (RFC 5545):
  BEGIN:VCALENDAR
  VERSION:2.0
  PRODID:-//Selvora//Reselling Calendar//EN
  CALSCALE:GREGORIAN
  METHOD:PUBLISH
  X-WR-CALNAME:Selvora Reselling Calendar
  REFRESH-INTERVAL;VALUE=DURATION:PT3H
  X-PUBLISHED-TTL:PT3H
  [for each event:]
  BEGIN:VEVENT
  UID:{id}@selvora
  DTSTART;VALUE=DATE:{YYYYMMDD}
  DTEND;VALUE=DATE:{YYYYMMDD or +1 day}
  SUMMARY:{type label}: {title}
  DESCRIPTION:{notes or empty}
  END:VEVENT
  END:VCALENDAR

NOTES:
  - REFRESH-INTERVAL and X-PUBLISHED-TTL hint to clients to poll every 3 hours
  - Google Calendar actually polls ~every 24h regardless; Apple Calendar respects the hint
  - User copies the feed URL and adds it via:
      Google: "Other calendars" → "+" → "From URL" → paste URL
      Apple:  File → New Calendar Subscription → paste URL
      Outlook: Add calendar → Subscribe from web → paste URL

DB change needed on User model:
  calendar_token  String?  @unique  // generated UUID, null until first requested

STEP 6 — FRONTEND HOOKS (selvora-app/src/hooks/useApi.js)
================================================================================

Add at bottom of file (before any closing code):

  // ─── Calendar Events ────────────────────────────────────────────────────────
  export const useCalendarEvents = (month) =>
    useQuery({
      queryKey: ['calendar-events', month],
      queryFn: () => fetcher(`/api/calendar-events?month=${month}`),
      enabled: !!month,
    });

  export const useCalendarAutoEvents = (month) =>
    useQuery({
      queryKey: ['calendar-auto-events', month],
      queryFn: () => fetcher(`/api/calendar-events/auto?month=${month}`),
      enabled: !!month,
      staleTime: 1000 * 60 * 5,
    });

  export const useCalendarMutations = () => {
    const qc = useQueryClient();
    const invalidate = () => qc.invalidateQueries({ queryKey: ['calendar-events'] });

    const create = useMutation({
      mutationFn: (data) => fetcher('/api/calendar-events', { method: 'POST', body: JSON.stringify(data) }),
      onSuccess: invalidate,
    });
    const update = useMutation({
      mutationFn: ({ id, ...data }) => fetcher(`/api/calendar-events/${id}`, { method: 'PUT', body: JSON.stringify(data) }),
      onSuccess: invalidate,
    });
    const remove = useMutation({
      mutationFn: (id) => fetcher(`/api/calendar-events/${id}`, { method: 'DELETE' }),
      onSuccess: invalidate,
    });

    return { create, update, remove };
  };

Also add to useInvalidate() return object:
  calendarEvents: () => qc.invalidateQueries({ queryKey: ['calendar-events'] }),
